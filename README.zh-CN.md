# Open Context Clipper · 文脉采集器

语言：[English](README.md) · **简体中文**

**把网页文章，带回自己的本地知识库。**

Open Context Clipper 是一款开源 Chrome 扩展。打开文章后点击扩展，先预览识别出的正文，再直接下载 Markdown，或保存到本地队列稍后整理。导出的文件可以放进自己的文件夹或 Markdown 知识库。文章的提取、转换和队列保存都在浏览器本机完成，无需注册账号，也不需要运行后端服务。

> 当前版本通过 Chrome 的“加载已解压的扩展程序”安装，尚未发布到 Chrome Web Store。

## 从网页到本地 Markdown

| 1. 主动采集 | 2. 集中管理 | 3. 自由导出 |
| --- | --- | --- |
| 点击扩展后预览标题、来源、正文片段等信息，可直接下载 Markdown 或保存到队列。 | 文章进入本地队列；可搜索、查看详情、添加备注和批量选择。 | 单篇下载 Markdown，多篇打包为 ZIP，也可导出所选记录的 JSON。 |

### 先看预览，再保存

在当前文章页点击扩展图标。弹窗会显示识别结果和正文预览；点击“导出 Markdown”可直接下载当前文章，不会加入队列，填写的备注也会写入文件；点击“保存到采集队列”才会把文章存入本地队列。关闭弹窗不会保存。

### 在浏览器窗口管理文章

点击“打开队列”，即可搜索已采集的文章、查看详情、重新打开来源，或按需导出。“收件箱”放待导出的内容，按采集时间倒序显示；下载开始后，记录进入“已完成”，方便近期查找和再次导出。列表支持批量选择，当前搜索结果也可以直接导出为 ZIP。

![满屏本地队列：搜索、查看详情和批量导出已采集文章](docs/images/local-queue.png)

### 导出后，继续用你熟悉的工具阅读

导出的 Markdown 保留文章标题、来源链接、采集时间、作者（如有）、备注（如有）和正文。文件名尽量采用网页标题；不适合文件名的字符会被替换，ZIP 内同名文章会加序号。它是普通文本文件，可以用 Typora 等 Markdown 编辑器打开，也可以放入自己的本地知识库目录，继续整理、检索或备份。

![导出的 Markdown 在 Typora 中打开](docs/images/markdown-in-typora.png)

## 快速开始

需要桌面版 Google Chrome、Node.js 和 npm。在仓库根目录运行：

```bash
npm ci
npm run build
```

然后打开 Chrome 的 `chrome://extensions`，开启“开发者模式”，点击“加载已解压的扩展程序”，选择本仓库生成的 `dist/` 目录。源码更新后，再运行 `npm run build`，并在扩展管理页重新加载扩展。

## 日常使用

1. 打开一篇已经加载完成的网页文章，点击工具栏中的 Open Context Clipper。
2. 核对标题、来源、作者、发布日期、字数、远程图片数量和正文预览；可选填一条备注。
3. 点击“导出 Markdown”直接下载且不写入队列，或点击“保存到采集队列”留待稍后处理。相同页面且正文未变化时，保存到队列会提示已有记录，避免无意重复保存。
4. 点击“打开队列”，在收件箱里从最新文章开始搜索、查看和选择。单篇用“导出 Markdown”；多篇用“导出所选 ZIP”或“导出全部 ZIP”。需要结构化备份时，可导出所选 JSON。
5. ZIP 中的 `articles/` 目录包含每篇文章的 Markdown，根目录的 `captures.json` 保存对应记录。把 Markdown 文件放进自己的本地知识库，或用喜欢的编辑器直接打开。

界面支持简体中文和英文，默认跟随 Chrome 语言。打开队列的「设置 → 界面语言」，可选择「跟随浏览器」「简体中文」或「English」。切换后队列立即更新，弹窗下次打开时生效；其他浏览器语言默认显示英文。Markdown 导出的固定元数据标签跟随界面语言，文章正文、标题和备注保持原样，JSON 字段名不变。

浏览器内部页面（例如 `chrome://`）无法采集，但弹窗里的“打开队列”仍可管理已经保存的文章。对于需要登录的页面，扩展只处理当前标签页**已经渲染出来**的内容，不会代替你登录或绕过付费墙。

## 本地数据与你的控制权

- **主动才读取：** 只有点击扩展采集当前标签页时，才会读取该页已渲染的内容；确认保存后才写入队列。不会后台轮询网页。
- **正文留在本机：** 提取和 Markdown 转换在浏览器内完成；保存到队列的记录放在扩展自己的 IndexedDB 中，直接导出不会创建队列记录。当前版本不会把采集正文上传到项目服务器、Open Context Forge 或其他同步服务。
- **按需导出：** 只有你点击导出时，扩展才会发起本地文件下载。扩展能确认下载已发起，不能确认文件最终成功保存；重要文章请检查下载结果。
- **有限权限：** 扩展使用当前标签页的临时访问权限，不读取或保存 cookies、登录凭据与浏览历史。
- **图片保持链接：** Markdown 保留远程图片 URL，不下载图片文件。之后在 Markdown 编辑器中打开文章时，显示这些图片可能仍需要访问原网站。

“已完成”默认永久保留在本地。你可以在队列的“设置”中改为保留 30 天或 90 天；到期清理只在下次打开队列时执行，不会清理收件箱。删除或自动清理的记录无法在扩展内恢复，建议先确认重要文件已导出。

扩展本地数据与安装的扩展 ID 绑定。卸载扩展可能清除队列；从旧安装路径重新加载也可能生成不同 ID，旧队列不会自动迁移。当前没有 JSON 导入功能，因此更换安装方式前请先导出需要保留的内容。

## 当前范围

本项目专注于把当前网页中已渲染的文章正文转成可带走的 Markdown。遇到尚未加载的内容、登录提示或付费墙预览，识别结果可能不完整；请在保存前查看预览。当前版本不提供云同步、自动抓取、AI 整理或向其他知识库自动写入。
